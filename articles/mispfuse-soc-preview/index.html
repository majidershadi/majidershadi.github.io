MISPFuse SOC Preview: Intelligence in the Investigation

Looking up an indicator is easy. Knowing whether the lookup finished, keeping its context, and reviewing what goes back to MISP take more care.

October 30, 2026Unreleased development workBy Majid Ershadi

MISPFuse started with the outbound path: move selected Splunk results into MISP through named accounts and reusable mappings. The next stage brings intelligence back into the investigation.

This is a development preview. The existing 2.2.4 article describes the released outbound workflow. The public package does not yet include the work described here.

Three analyst workspaces

Investigate searches MISP attributes and events. It shows source context and a separate completion status. A partial lookup is not a clean negative result.

Intelligence Library shows a bounded, manually refreshed snapshot and its freshness. A partial refresh keeps the previous active generation. It is not yet a scheduled incremental synchronization service.

Contribute previews an operation before submission. The current page handles a single indicator, existing-event append, sightings and separate publication. The new submission path claims an operation ID before sending; uncertain delivery requires reconciliation instead of an automatic resend.

A practical investigation

Take a domain from a DNS alert, search the selected MISP account, and examine the event behind the match. Enrich the Splunk result while retaining the original observation in a separate JSON envelope. If the observation adds useful evidence, review a sighting or contribution rather than creating another event by habit.

Start with synthetic data such as triage.example.test or 192.0.2.44. These examples are not threat indicators.

Permissions are part of the workflow

The new commands require both an operation-specific capability and an account role allowlist. Collection and submission need administrator-provisioned, account-scoped KV Store collections. Default configuration grants no account access. Use least-privilege MISP credentials and verified TLS for remote deployments.

What the lab caught

Tests against isolated Docker MISP 2.5.50 exercised creation, attribute and event searches, enrichment, append, sightings and publication. They caught a publication-response mismatch. The corrected path reads back the event state before reporting publication as confirmed.

Testing through Splunk also caught a CSV output issue: status columns appearing only after data rows could be lost. Declaring a consistent output schema preserves the terminal status.

A development package produced zero errors and zero failures in Linux AppInspect, but warnings and a future-failure flag still need review. That is not online acceptance or a final-release result.

What is still outstanding

Scheduled incremental sync, retention cleanup, cluster failover qualification, Enterprise Security export, a visual bulk/object editor and automatic migration are not complete. The MISP42 inventory helper identifies searches to review; it does not disable or replace them.

Full replacement of another integration must be earned through side-by-side comparisons of the searches and alerts a team actually uses.
